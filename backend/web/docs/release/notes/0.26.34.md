# Orbitly 0.26.34

Android app and server update: a "Keep tracking alive" checklist, tracking that restarts itself where Android allows it, and a fix for "driving at 0 mph".

## Keeping tracking alive (the app and the server)


### New
- **A "Keep tracking alive" checklist** in **Settings > Advanced**. It shows, live, whether Orbitly can keep sharing with the screen off: location "Allow all the time", battery "Unrestricted", Android's power group for the app, notifications, and whether the sharing service is running. Each thing that is wrong has a button that takes you to the right place. The list updates when you come back from the settings page.
- **Orbitly now tries to restart sharing by itself** when Android has stopped the service and you did not turn sharing off. Android only allows that in some cases (the clearest one: Orbitly is set to Unrestricted battery), so a restart can still be refused. The checklist and Diagnostics say when that happened and why.
- **Your server now nudges a phone that has gone quiet.** If a phone that is sharing has not reported for 30 minutes, the server asks it for a fresh position (at most once every 15 minutes and 12 times a day, never while you have paused sharing, never more than 8 times in a row without an answer). Update the server for this part.

### Samsung phones
Samsung's **Never auto sleeping apps** list may say "No apps" when you search for Orbitly. We think that is because Samsung leaves out apps that are already Unrestricted, but we could not confirm that on your phone. Orbitly cannot add itself to that list. Set **Settings > Apps > Orbitly > Battery > Unrestricted** instead, then check once that Orbitly is not under **Sleeping apps** or **Deep sleeping apps** (Settings > Battery > Background usage limits). The checklist shows a grey "check once" line when Android reports Orbitly as Unrestricted, and does not turn fully green on a Samsung phone, because Orbitly cannot read Samsung's own lists.

### Limits
- If you or the phone force-stop Orbitly (Samsung's sleeping apps do that), nothing can restart it until you open it.
- Android decides in the end. This update cannot promise sharing in the background "no matter what".

## Not tried on a real device yet
Nothing in this part was run on a phone. It was checked on a computer only and the Android parts were not built into an app. We do not know yet whether it fixes the phone that stopped sharing.

## Driving at 0 mph (the app)

### Fixed
- **"Driving at 0 mph" is gone.** A family member who is sitting still no longer shows as driving at 0 mph. A car at a red light now shows **Stopped**; once someone has been still for a few minutes, or Orbitly has had no new position for two minutes, they are no longer shown as driving at all. When the phone gives no speed, Orbitly shows **Driving** without a number instead of a made-up 0. The same wording is used on the map, in the list, in the person's card, in the widget and on the watch.

This part was checked on a computer only; the Android part was not built into an app and nothing was run on a phone. The web map is not changed yet.

## Server: Dawarich sync (needs the new server image)
If you send history to your own Dawarich server and it goes down, Orbitly no longer asks it every minute and fills the server log with the same warning. It now waits longer after each failure (2, 4, 8, 16, 32 minutes, then an hour), writes the problem to the log once, and shows it on **Settings > Integrations**: what failed, how many times in a row, when it tries next and when something last arrived. Nothing is lost while it waits; the points are sent later. Saving the settings or pressing **Sync now** tries at once. This is server-side only (update the server image; the admin web page changed too). It was tested on a computer with a fake Dawarich server, not with a real one.

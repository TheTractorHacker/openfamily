# Orbitly 0.26.28

**Update the server first, then the phones.** The server update changes nothing you have to do by hand; phones on older versions keep working.

## New
- **Resetting your encryption keys no longer breaks the circle.** The server keeps its own key through the reset, so the other members do not have to do anything and nobody is asked to approve the server again.
- **"Require server processing" is one switch for the circle owner.** Turn it on in the circle settings and every member's phone switches itself over, with no prompts. The honest consequence: a member who does not want it can only leave the circle.
- **Your encryption key now survives deleting and reinstalling the app.** Install again, sign in to the same account, and the key comes back by itself, but only if the server still lists it as active. (Android: Google Play services; iPhone: the keychain.)
- **The phone checks the server's key itself** before it signs anything for it, so a server that lies about its key cannot talk a phone into trusting it.

## Fixed
- The **Server processing** screen no longer ends on "Something went wrong". It says what happened (no connection, waiting for approval, key problem, ...) and what the app does about it.
- **Diagnostics > Private circle delivery** is written in plain words. The technical lines stay in the copied report.
- The built-in server finds its way back after a reset by itself, even after a restart in the middle of it.

## Before you update
- In a circle that requires server processing, a member on an older app sees "(update the app to keep sharing with this circle)" until they update.
- For 72 hours after a server key is replaced, a member who has not signed the new key yet can still deliver; after that they are refused until their phone signs.

## Not tried on a real device yet
Everything above was tested on a computer only. Not yet seen on a phone: the key coming back after a reinstall, and a full key reset on a live circle. If a reset or reinstall goes wrong, **Diagnostics > Send now** helps us see why.
